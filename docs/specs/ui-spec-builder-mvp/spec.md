# UI Spec Builder MVP

스크린샷 한 장에서 영역을 고르고 토큰 이름을 입력해, AI가 그대로 구현할 수 있는 스펙 .md와 주석 이미지를 만드는 브라우저 전용 앱의 첫 범위입니다. 용어는 [GLOSSARY.md](../../../GLOSSARY.md)를 따릅니다.

## 사용자 가시 결과

- 개발자가 스크린샷을 올리고, 앱이 만든 프롬프트로 Copilot에게서 영역 초안을 받아 붙여넣으면 화면 위에 노드 박스가 나타납니다.
- 박스를 보정하고 계층을 따라 내려가며 노드를 고르면 입력 패널이 뜨고, 토큰 이름을 직접 입력합니다.
- 입력한 값만 담긴 스펙 .md와 주석 이미지를 내려받습니다. 두 파일만으로 Copilot이 토큰을 하드코딩 없이 참조해 UI를 구현할 수 있습니다.

## 범위

**포함**

- 스크린샷 업로드
- 프롬프트 복사와 영역 초안 붙여넣기, 검증, 오류 안내
- 박스 드래그 보정, 추가, 삭제, 자동 자식 편입
- 드릴다운 선택과 키보드 이동
- 노드 종류별 토큰 이름 입력(선택 입력)과 입력 현황
- 스펙 .md와 주석 이미지 내보내기
- 작업 내용의 새로고침 후 유지

**제외 (이후 단계)**

- AI 자동 호출
- 템플릿 저장
- 구현 결과 시각 diff 검증
- 토큰 카탈로그(.yaml) 불러오기, 자동완성, 카탈로그에 없는 이름 경고

## 동작

### 1. 스크린샷 업로드

- 이미지 파일을 올리면 화면에 표시합니다. 파일 선택창, 끌어다 놓기, Ctrl+V 붙여넣기 세 가지로 올릴 수 있습니다. 사내 환경에서 파일 선택창이 막혀 있어도 화면 캡처를 복사해 붙여넣을 수 있게 하기 위해서입니다. 텍스트를 붙여넣는 동작은 방해하지 않습니다.
- 이미지는 브라우저 안에서만 처리하며 외부로 전송하지 않습니다.

### 2. 영역 초안 연동

**프롬프트 복사**

- 앱이 지시문이 담긴 프롬프트를 화면에 보여 주고, [프롬프트 복사] 버튼으로 복사하게 합니다. 사용자는 복사 전에 내용을 읽고 확인할 수 있습니다. 프롬프트의 권장 문안은 [draft-prompt.md](draft-prompt.md)이며, 다음을 요구합니다.
  - JSON만 응답한다.
  - 하나의 루트 노드를 가진 단일 트리로 응답한다.
  - 노드마다 `id`(중복 없음), `type`, `bounds`를 준다.
  - `type`은 `frame`, `text`, `shape`, `icon` 중 하나다. `icon`은 Icon/Image 종류를 뜻한다.
  - `bounds`는 `[x, y, w, h]` 순서이고, 이미지 전체 크기에 대한 0～1 비율이다.
  - 텍스트 노드는 `text`에 문구를 담고, 항상 Frame의 자식으로 둔다.
  - 배경과 radius를 가진 요소는 Frame으로 표현하고, Shape는 안에 아무것도 없는 단독 도형에만 쓴다.
  - 색, 글꼴 크기 같은 값은 요구하지 않는다.

**붙여넣기와 검증**

- 사용자가 응답 JSON을 붙여넣으면 앱이 검증합니다. 응답이 코드 블록(```json)으로 감싸져 있어도 같은 JSON으로 읽습니다.
- 오류로 막는 경우: JSON 형식 오류, 필수 필드 누락(`id`, `type`, `bounds`, 텍스트 노드의 `text`), 알 수 없는 `type`, 중복 `id`, 루트가 둘 이상, `bounds`의 값이 0～1 범위 밖이거나 `x+w`, `y+h`가 1을 넘는 경우(0.01 이내 오차는 허용).
- 경고만 하고 받아들이는 경우: 자식이 부모 박스를 벗어난 경우(0.01 이내 오차는 경고도 내지 않음).
- 오류가 있으면 어느 노드의 어떤 항목이 틀렸는지 알려 주고, 수정 요청용 문구를 복사할 수 있게 제공합니다. 문구에는 틀린 항목이 구체적으로 들어가며, 모양은 [draft-prompt.md](draft-prompt.md)의 수정 요청 문구를 따릅니다.
- 검증을 통과하면 박스를 화면에 표시하고, 이 트리가 작업의 기준 트리가 됩니다. 같은 이미지로 Copilot을 다시 호출해도 기준 트리는 바뀌지 않으며, 사용자가 새 JSON을 붙여넣을 때만 교체됩니다.

### 3. 박스 보정

- 박스를 드래그해 위치와 크기를 바꿀 수 있습니다.
- 박스를 새로 추가할 수 있습니다. 다른 박스 안에 완전히 들어가면 가장 안쪽 박스의 자식이 됩니다.
- 박스를 삭제할 수 있습니다. 삭제된 노드의 자식은 삭제된 노드의 부모로 올라가 이어집니다.
- 보정은 즉시 반영되며, 이미 입력한 토큰 값은 유지됩니다.

### 4. 드릴다운 선택

- 클릭은 현재 깊이의 가장 큰 영역(최상위)을 고릅니다. 더블클릭이나 Enter는 고른 노드의 자식으로, Shift+Enter는 부모로 이동합니다. Tab은 형제 노드로 옮깁니다.
- 지금 보는 범위 밖의 영역을 누르면, 그 점을 담는 가장 가까운 조상 범위까지 올라가 그 영역의 같은 깊이 노드를 고릅니다. 다른 가지의 영역도 막힘 없이 바로 이동할 수 있습니다.
- 마우스를 올리면 그 영역이 강조됩니다.
- 초안의 모든 노드를 들여쓴 구조 목록으로도 보여 주며, 목록의 항목을 누르면 깊이와 상관없이 그 노드를 바로 선택합니다. 스크린샷에서 고르기 어려운 작은 요소(아이콘, 문구)를 위한 것입니다.
- 노드가 선택되면 입력 패널이 자동으로 뜨고, 이미 입력한 값이 함께 보입니다.

### 5. 토큰 입력

모든 값은 토큰 이름(hex나 px이 아님)이며, 기본값은 없습니다. 각 필드는 텍스트 입력 하나이고 **모두 선택 입력**입니다. 비워 둔 필드는 스펙 .md에 만들지 않으며, 앱은 그 값을 추정해 채우지 않습니다.

| 노드 종류 | 필드 |
|---|---|
| Frame | 레이아웃(방향, 정렬, 간격), 색상, 테두리(border, radius), 그림자·블러 |
| Text | 레이아웃(정렬), 색상, 타이포 (문구는 초안 값이 채워져 있고 수정 가능) |
| Shape | 색상, 테두리, 그림자·블러 |
| Icon/Image | 에셋 이름 또는 경로, 색상 |

- 레이아웃(정렬, 간격)은 Frame에, 문구와 글꼴 스타일은 Text에 둡니다.
- 프로젝트 단위로 대상 스택도 텍스트로 입력할 수 있고, 선택입니다.
- 입력한 필드 수와 입력할 수 있는 전체 필드 수를 보여 주고, 노드마다 입력 현황을 표시합니다. 이는 현황 표시일 뿐 내보내기의 조건이 아닙니다.

### 6. 내보내기

영역 초안이 적용되어 있으면 값을 얼마나 입력했는지와 상관없이 내보낼 수 있습니다. 입력하지 않은 필드는 .md에 쓰지 않습니다.

**스펙 .md** 에는 다음이 들어갑니다.

- 개요, 대상 스택
- 주석 이미지의 상대 경로 참조, 그리고 "이미지는 참고용이고 기준은 이 문서의 텍스트 스펙"이라는 안내
- 노드 ID와 주석 이미지의 번호를 함께 적은 계층 트리
- 노드별 스펙: 부모, 순서, 입력한 토큰 이름. 크기 비율은 Copilot 좌표가 근사값이라 쓰지 않습니다.
- 동적 바인딩 목록: 문구에 `{{...}}`가 있는 텍스트 노드를 자동으로 모아 보여 줍니다.
- 구현 지시문: 토큰은 CSS 변수나 테마로 참조하고 값을 하드코딩하지 않습니다.

**주석 이미지**는 모든 노드를 박스와 번호로 그린 전체 화면 1장이며, 긴 변이 1500～2000px입니다.

사용자가 파일 이름을 하나 정하면 .md와 이미지가 같은 이름으로 만들어집니다(기본값은 올린 스크린샷 이름, 예: `카드.md`와 `카드.png`). 이름의 공백과 파일 이름에 쓸 수 없는 문자는 `-`로 바뀝니다. 저장 방법은 두 가지입니다.

- **저장 위치를 골라 저장:** 브라우저의 폴더 선택 창으로 폴더를 고르면 그 폴더에 두 파일을 저장합니다. 같은 이름의 파일이 있으면 덮어씁니다. 폴더 선택은 사용자의 클릭 직후에 열고, 취소와 쓰기 권한 거부는 브라우저가 구분해 주지 않으므로 같은 안내로 처리합니다. 이 창을 지원하지 않는 브라우저에서는 이 방법이 나타나지 않습니다.
- **다운로드 폴더로 내려받기:** 브라우저의 기본 다운로드 폴더로 두 파일을 내려받습니다. 폴더 선택 창이 막힌 환경에서도 쓸 수 있습니다.

.md는 같은 폴더의 이미지를 상대 경로로 참조합니다.

### 7. 작업 유지

- 올린 이미지, 확정한 트리, 입력한 값이 새로고침 후에도 남습니다. 한 번에 하나의 작업만 보관하며, 새 스크린샷을 올리면 이전 작업을 대체합니다. 이 동작은 템플릿 저장과 다릅니다.

## 수용 기준

[fixtures/notification-card.png](fixtures/notification-card.png)와 [fixtures/notification-card.json](fixtures/notification-card.json)(권장 프롬프트로 얻은 실제 Copilot 응답, 공백만 정리하고 값은 그대로)을 기준 화면으로 씁니다.

1. 위 JSON을 붙여넣으면 오류 없이 박스가 표시됩니다. 이 JSON에서 `description`이 부모 박스를 벗어나므로 해당 노드에 경고가 표시되고, 작업은 막히지 않습니다.
2. 아래 입력은 각각 막히고, 어느 노드의 어떤 항목이 틀렸는지 안내하며 복사 가능한 수정 요청 문구를 보여 줍니다: JSON이 아닌 텍스트, `bounds` 값이 1.2인 노드, `type`이 `button`인 노드, 중복 `id`.
3. 화면에 프롬프트 전문이 보이고, 프롬프트 복사를 누르면 같은 내용이 클립보드에 복사됩니다. 프롬프트에는 "동작 2"의 모든 요구가 담겨 있습니다. 코드 블록으로 감싼 응답 JSON도 오류 없이 읽힙니다.
4. 박스를 드래그하면 위치가 바뀌고, 이미 입력한 토큰 값은 유지됩니다. 다른 박스 안에 새 박스를 그리면 그 박스의 자식이 되고, 노드를 삭제하면 자식이 삭제된 노드의 부모 밑으로 올라갑니다.
5. 클릭, 더블클릭, Enter, Shift+Enter, Tab으로 계층을 이동할 수 있고, 마우스를 올린 영역이 강조됩니다. 버튼 영역을 선택한 뒤 헤더 영역을 눌러도 헤더로 이동합니다. 구조 목록에서 `title_text`, `description_text`, `left_button` 같은 안쪽 노드를 한 번에 선택할 수 있습니다.
6. 노드를 선택하면 종류에 맞는 입력 필드가 바로 뜨고, 이미 입력한 값이 채워져 있습니다.
7. 값을 하나도 입력하지 않아도 내보낼 수 있습니다. 입력한 필드만 .md에 나타나고, 입력이 없는 노드는 "입력된 토큰 없음"으로 표시됩니다. 입력 현황은 입력한 필드 수 대 전체 필드 수로 보입니다.
8. 파일 이름을 정하고 내보내면 같은 이름의 .md와 이미지 두 파일이 만들어집니다(이름 입력란에 쓴 이름이 두 파일에 똑같이 쓰입니다). 폴더 선택 창을 지원하는 브라우저에서는 고른 폴더에 저장되고, 선택을 취소하거나 쓰기 권한이 거부되면 저장하지 않았다는 안내와 다운로드 폴더 방법이 표시되며, 다운로드 폴더로 내려받는 방법도 항상 쓸 수 있습니다. 이미지의 긴 변은 1500～2000px이고 모든 노드에 번호 박스가 그려져 있습니다. .md의 이미지 참조는 상대 경로이며, 계층 트리의 노드 번호가 이미지의 번호와 일치합니다.
9. .md에는 hex나 px 값이 없고 토큰 이름만 있으며, `{{NN}}%`가 동적 바인딩 목록에 나타납니다.
10. 새로고침 후에도 이미지, 트리, 입력한 값이 그대로 남습니다.
11. 서버 호출과 외부 전송이 없습니다. 이미지가 네트워크로 나가는 요청이 없음을 브라우저에서 확인할 수 있습니다.

## 확정된 제약과 근거

- **서버, API 키, 환경 변수 없이 브라우저에서만 동작합니다.** 앱용 AI 접근을 확보하기 어렵고, 사내 정책상 이미지는 사용자가 승인된 Copilot에 직접 올려야 합니다.
- **영역 초안은 복사와 붙여넣기로 연동합니다.** 좌표는 이미지 대비 0～1 비율이며, 이는 이미지 크기가 달라도 쓸 수 있게 하기 위해서입니다. 실제 시험에서 픽셀 좌표를 받았을 때 이미지 크기와 몇 픽셀씩 어긋나 이 방식을 유지합니다.
- **토큰 값은 직접 입력하는 텍스트입니다.** 카탈로그 연동은 구조 확인과 구현 비용 때문에 이후 단계로 둡니다. 이 때문에 앱은 오타를 잡아 주지 못합니다.
- **이미지는 참고용이고 값의 기준은 .md의 텍스트입니다.** 이미지가 인식되지 않아도 .md만으로 구현할 수 있어야 합니다.
- **배경, 테두리, 그림자를 가진 요소는 Frame입니다.** Shape는 안에 아무것도 없는 단독 도형에만 씁니다. Copilot의 응답 트리를 그대로 살릴 수 있고 입력할 노드 수가 줄어듭니다. 대신 Frame의 필드가 늘어납니다.
- **텍스트가 있는 요소는 Frame 아래 Text 구조입니다.**
- **Figma 연동은 사용하지 않습니다.** 사내 정책상 불가합니다.
- **일반 UI는 [ui-composition](../../decisions/ui-composition.md) 결정을 따릅니다.** 입력 패널, 진행률, 버튼 등 일반 UI에 적용되며, 스크린샷 위의 박스 표면만 직접 구현할 수 있습니다.

## 가정 (바꾸고 싶으면 말씀해 주세요)

- 포함 관계 위반은 경고로만 처리하고 0.01 이내 오차는 조용히 허용합니다. 박스 보정으로 사용자가 고칠 수 있기 때문입니다.
- 입력하지 않은 값은 .md에 만들지 않고, .md가 그 값을 추정해 채우지 말라고 구현자(AI)에게 명시합니다. 값을 추정하지 않는다는 원칙을 지키면서 필요한 값만 입력하게 하기 위해서입니다.
- 내보내기는 .md와 이미지 두 파일을 따로 만드는 방식입니다. 압축 파일은 쓰지 않습니다. 사용자가 Copilot 채팅에 파일을 바로 첨부할 수 있기 때문입니다.
- 노드를 삭제하면 자식은 부모 밑으로 올라갑니다. 트리를 의도치 않게 잃지 않게 하기 위해서입니다.
- 한 번에 하나의 작업만 보관합니다.
- 주석 이미지에는 모든 노드를 그립니다.

## 범위 밖과 이유

- AI 자동 호출: 앱용 API 접근이 없습니다. 나중에 접근이 생기면 [자동 생성] 버튼만 더하는 확장이 가능하도록 연동 지점을 막지 않습니다.
- 템플릿 저장, 시각 diff 검증: 이후 단계입니다.
- 그림자, 그라디언트, 투명도, 상태별 변형: 이번 필드로는 표현하지 않습니다.
- `docs/decisions/`에 새 결정 문서는 만들지 않았습니다. 이 범위의 결정은 모두 이 앱 안에서만 쓰입니다.

## 보류

- **토큰 카탈로그(.yaml) 연동:** 실제 파일 구조를 아직 모릅니다. 구조를 받으면 자동완성과 경고를 다시 판단합니다. 그때까지는 위의 직접 입력이 현재 동작입니다.
- **에셋 지정(Icon/Image):** 에셋 이름이나 경로를 텍스트로 입력합니다(임시). 실제 에셋 체계가 정해지면 바꿉니다.
- **Copilot의 .md 이해:** .md가 이미지 참조를 따라 이미지를 읽는지, 채팅에 직접 첨부해야 하는지, 이미지 없이 텍스트만으로 충분한지는 첫 내보내기 결과로 시험합니다. 그때까지 .md는 이미지 없이도 구현할 수 있게 쓰고, 이미지는 채팅에 함께 첨부하라는 안내를 .md에 둡니다.

## 남은 위험

- 복사와 붙여넣기 단계가 자동 호출보다 번거롭습니다.
- 권장 프롬프트([draft-prompt.md](draft-prompt.md))는 알림 카드 한 화면에서 한 번 시험했고, 형식(종류, 비율 좌표, 단일 트리, id, 텍스트는 Frame 아래)을 모두 지켰습니다. 다른 화면에서도 같은지는 구현 때 다시 확인해야 합니다.
- 좌표는 근사값이라 보정 작업이 필요합니다. 작은 요소(아이콘, 셰브론)는 선택이 어려울 수 있습니다.
- 알림 카드 한 장에도 노드가 24개이고 입력할 수 있는 필드가 많습니다. 필요한 값만 입력하면 되지만, 템플릿 저장이 없으니 반복 화면은 매번 처음부터 입력합니다. 입력이 없는 노드는 .md에서 값이 비므로 구현 결과가 설계와 달라질 수 있습니다.
- 주석 이미지에 작은 노드가 많으면 번호가 겹쳐 보일 수 있습니다.
- 토큰을 직접 입력하므로 오타가 .md에 그대로 들어갑니다.
- AI 도구가 이미지를 읽지 못하면 텍스트 스펙만으로 구현해야 해서 오차가 늘 수 있습니다.
